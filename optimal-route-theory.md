# Исследование задачи построения оптимального маршрута

## Введение

Задача построения оптимального маршрута возникает в транспортной логистике, навигационных системах, сетевой маршрутизации, робототехнике, игровых алгоритмах и планировании перемещений. В общем виде требуется найти такой путь между объектами, который является наилучшим по заданному критерию: минимальная длина, минимальное время, минимальная стоимость, наименьшее число переходов или другая величина.

В рамках данной работы под оптимальным маршрутом рассматривается прежде всего задача кратчайшего пути в графе. Это классическая постановка, в которой объекты представляются вершинами графа, а возможные переходы между ними - ребрами с весами.

## Формальная постановка задачи

Пусть задан граф:

```text
G = (V, E)
```

где:

- `V` - множество вершин графа;
- `E` - множество ребер, соединяющих вершины;
- `w(u, v)` - вес ребра между вершинами `u` и `v`;
- `s` - начальная вершина маршрута;
- `t` - конечная вершина маршрута.

Необходимо найти путь:

```text
s -> ... -> t
```

для которого сумма весов входящих в него ребер минимальна:

```text
min sum(w(u, v))
```

Граф может быть ориентированным или неориентированным. В ориентированном графе ребро имеет направление, например `u -> v`, и движение в обратную сторону может быть запрещено или иметь другой вес. В неориентированном графе переход между двумя вершинами возможен в обе стороны.

Вес ребра может обозначать:

- расстояние между пунктами;
- время движения;
- стоимость перехода;
- уровень риска;
- количество ресурсов, необходимых для перемещения.

Критерий оптимальности зависит от прикладной задачи. В данной работе основным критерием считается минимальная суммарная стоимость маршрута.

## Классификация задач маршрутизации

### Кратчайший путь между двумя вершинами

В этой постановке требуется найти оптимальный маршрут от одной заданной вершины `s` до другой заданной вершины `t`. Такая задача часто встречается в навигации, когда пользователь указывает точку отправления и точку назначения.

Для решения применяются, например, алгоритм Дейкстры, A* и Беллмана-Форда.

### Кратчайшие пути от одной вершины до всех остальных

Здесь требуется найти оптимальные расстояния от стартовой вершины `s` до всех остальных вершин графа. Такая постановка полезна, если из одного источника нужно построить маршруты сразу ко множеству пунктов.

Типичные алгоритмы: BFS для невзвешенных графов, Дейкстра для графов с неотрицательными весами, Беллман-Форд при наличии отрицательных весов.

### Кратчайшие пути между всеми парами вершин

В этой задаче необходимо найти кратчайшие расстояния между каждой парой вершин графа. Она применяется, когда нужно заранее подготовить таблицу расстояний для всех возможных маршрутов.

Классический алгоритм для такой постановки - Флойд-Уоршелл.

### Отличие от задачи коммивояжера

Задача кратчайшего пути не требует посещения всех вершин графа. Нужно найти лучший путь между заданными точками.

Задача коммивояжера, или TSP, формулируется иначе: необходимо посетить все заданные пункты ровно один раз и вернуться в начальную точку так, чтобы суммарная длина маршрута была минимальной. Это более сложная комбинаторная задача, которая относится к NP-трудным задачам.

Таким образом, кратчайший путь и задача коммивояжера относятся к маршрутизации, но имеют разные условия, алгоритмы и вычислительную сложность.

## Основные алгоритмы решения

### Поиск в ширину, BFS

BFS применяется для поиска кратчайшего пути в невзвешенном графе, где все ребра имеют одинаковую стоимость. Алгоритм начинает обход из стартовой вершины и постепенно посещает вершины на расстоянии одного ребра, затем двух ребер и так далее.

Идея работы:

1. Поместить стартовую вершину в очередь.
2. Извлекать вершины из очереди в порядке добавления.
3. Просматривать всех непосещенных соседей текущей вершины.
4. Запоминать расстояние и предка для восстановления пути.

Применимость:

- невзвешенные графы;
- графы, где каждое ребро имеет одинаковую стоимость;
- поиск минимального количества переходов.

Сложность:

```text
O(V + E)
```

Преимущества:

- простая реализация;
- гарантирует кратчайший путь по числу ребер;
- хорошо подходит для будущей реализации на Go с использованием очереди.

Ограничения:

- не учитывает разные веса ребер;
- не подходит для задач, где расстояния или стоимости переходов различаются.

### Алгоритм Дейкстры

Алгоритм Дейкстры используется для поиска кратчайших путей в графе с неотрицательными весами ребер. Он постепенно выбирает вершину с минимальным известным расстоянием от старта и обновляет расстояния до ее соседей.

Идея работы:

1. Для стартовой вершины установить расстояние `0`.
2. Для всех остальных вершин установить расстояние как бесконечность.
3. Выбирать непосещенную вершину с минимальным текущим расстоянием.
4. Обновлять расстояния до соседних вершин, если найден более короткий путь.
5. Повторять процесс, пока не будут обработаны нужные вершины.

Применимость:

- взвешенные графы;
- веса ребер должны быть неотрицательными;
- поиск маршрутов в дорожных и сетевых графах.

Сложность:

```text
O((V + E) log V)
```

Такая сложность достигается при использовании очереди с приоритетом, например бинарной кучи.

Преимущества:

- эффективен для больших разреженных графов;
- хорошо подходит для задач навигации;
- может находить пути от одной вершины до всех остальных;
- удобно реализуется на Go через пакет `container/heap`.

Ограничения:

- некорректно работает при наличии отрицательных весов ребер;
- без очереди с приоритетом может быть менее эффективным.

### Алгоритм Беллмана-Форда

Алгоритм Беллмана-Форда решает задачу кратчайших путей от одной вершины до всех остальных и допускает отрицательные веса ребер. Кроме того, он позволяет обнаруживать отрицательные циклы.

Идея работы:

1. Установить расстояние до стартовой вершины равным `0`, до остальных - бесконечностью.
2. Повторить `V - 1` раз обновление всех ребер графа.
3. Если после этого можно еще раз уменьшить расстояние, значит в графе есть отрицательный цикл.

Применимость:

- графы с отрицательными весами;
- задачи, где важно обнаружить отрицательные циклы;
- ситуации, когда алгоритм Дейкстры применять нельзя.

Сложность:

```text
O(V * E)
```

Преимущества:

- работает с отрицательными весами;
- обнаруживает отрицательные циклы;
- логика алгоритма относительно проста.

Ограничения:

- медленнее алгоритма Дейкстры на больших графах;
- не имеет смысла для маршрута, если отрицательный цикл позволяет бесконечно уменьшать стоимость пути.

### Алгоритм Флойда-Уоршелла

Алгоритм Флойда-Уоршелла предназначен для поиска кратчайших путей между всеми парами вершин. Он использует динамическое программирование и постепенно проверяет, можно ли улучшить путь между двумя вершинами через промежуточную вершину.

Идея работы:

1. Создать матрицу расстояний между всеми парами вершин.
2. Расстояние от вершины до самой себя установить равным `0`.
3. Для существующих ребер записать их веса.
4. Последовательно рассматривать каждую вершину как промежуточную.
5. Обновлять расстояние `dist[i][j]`, если путь через промежуточную вершину короче.

Применимость:

- плотные графы небольшого или среднего размера;
- задачи, где нужны расстояния между всеми парами вершин;
- предварительный расчет таблицы маршрутов.

Сложность:

```text
O(V^3)
```

Преимущества:

- простой и компактный алгоритм;
- находит расстояния между всеми парами вершин;
- может работать с отрицательными ребрами, если нет отрицательных циклов.

Ограничения:

- высокая временная сложность;
- требует матрицу размера `V * V`;
- плохо подходит для очень больших графов.

### Алгоритм A*

Алгоритм A* является развитием идеи Дейкстры. Он использует не только уже пройденную стоимость пути, но и эвристическую оценку расстояния до цели. Это позволяет быстрее направлять поиск в сторону конечной вершины.

Для каждой вершины вычисляется значение:

```text
f(n) = g(n) + h(n)
```

где:

- `g(n)` - известная стоимость пути от старта до вершины `n`;
- `h(n)` - эвристическая оценка стоимости от вершины `n` до цели;
- `f(n)` - итоговый приоритет вершины.

Идея работы:

1. Начать поиск из стартовой вершины.
2. Для каждой вершины учитывать стоимость уже найденного пути и эвристическую оценку до цели.
3. В первую очередь рассматривать вершины с минимальным значением `f(n)`.
4. Завершить поиск при достижении конечной вершины.

Применимость:

- навигация на картах;
- поиск пути на сетках;
- игровые карты;
- случаи, когда известна допустимая эвристика.

Сложность:

```text
O((V + E) log V)
```

На практике A* часто быстрее Дейкстры, но эффективность сильно зависит от качества эвристики.

Преимущества:

- направляет поиск к цели;
- может значительно сократить количество просмотренных вершин;
- удобен для задач с координатами, где можно использовать евклидово или манхэттенское расстояние.

Ограничения:

- требует корректной эвристики;
- при плохой эвристике может работать почти как Дейкстра;
- если эвристика переоценивает расстояние, алгоритм может не гарантировать оптимальность.

## Сравнение алгоритмов

| Алгоритм | Тип графа | Что находит | Вес ребер | Сложность | Основное преимущество | Основное ограничение |
| --- | --- | --- | --- | --- | --- | --- |
| BFS | Невзвешенный | Кратчайший путь по числу ребер | Одинаковые веса | `O(V + E)` | Простота и высокая скорость | Не учитывает разные веса |
| Дейкстра | Взвешенный | Пути от одной вершины | Только неотрицательные | `O((V + E) log V)` | Эффективен для дорожных графов | Нельзя использовать с отрицательными весами |
| Беллман-Форд | Взвешенный | Пути от одной вершины | Допускает отрицательные | `O(V * E)` | Находит отрицательные циклы | Медленнее Дейкстры |
| Флойд-Уоршелл | Взвешенный | Пути между всеми парами | Допускает отрицательные без отрицательных циклов | `O(V^3)` | Прост для всех пар вершин | Требует много времени и памяти |
| A* | Взвешенный | Путь от старта к цели | Обычно неотрицательные | `O((V + E) log V)` | Быстро ищет путь к конкретной цели | Требует хорошей эвристики |

## Выбор алгоритмов для дальнейшей реализации на Go

Для практической реализации на Go целесообразно выбрать несколько алгоритмов, которые покрывают разные случаи:

1. BFS - базовый алгоритм для невзвешенных графов.
2. Дейкстра - основной алгоритм для взвешенных графов с неотрицательными ребрами.
3. Беллман-Форд - алгоритм для графов с отрицательными весами и проверки отрицательных циклов.
4. A* - алгоритм для маршрутизации с координатами и эвристической оценкой.

Флойд-Уоршелл также полезен для исследования, но его стоит реализовывать отдельно, если в работе требуется находить расстояния между всеми парами вершин. Для первой практической части достаточно начать с BFS, Дейкстры и Беллмана-Форда, а затем добавить A* как более прикладной алгоритм навигации.

## Заключение

Задача построения оптимального маршрута может иметь разные постановки, но одной из наиболее распространенных является задача кратчайшего пути в графе. Выбор алгоритма зависит от свойств графа: наличия весов, отрицательных ребер, необходимости найти один путь или все пути, а также доступности эвристической информации.

Для будущей реализации на Go наиболее важными являются алгоритмы BFS, Дейкстры, Беллмана-Форда и A*. Они позволяют рассмотреть основные классы задач и сравнить подходы по эффективности, ограничениям и применимости.
